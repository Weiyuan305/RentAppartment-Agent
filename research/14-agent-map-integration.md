2026-10-09。实现范围：五城样本、单 Node 进程。已使用用户本地配置的真实 OpenAI 兼容接口完成伦敦多轮工具调用验证，其他城市的真实模型流程尚未逐一验收。

## 已实现

- AI SDK 7.0.136 `ToolLoopAgent`、React 4.0.139、OpenAI provider 4.0.91，使用 Chat Completions 兼容接口与 SSE 流式输出。
- 工具：`searchListings`、`selectListing`、`findNearbyAmenities`、`focusAmenity`、`planWalkingRoute`。同一轮串行执行，最多 5 步、8 次工具调用、90 秒；每次模型输出最多 2400 token，关闭自动模型重试。
- 查询和 Cesium 共用 `selectAmenities`：完整收录数量与地图点位一致；模型只收到最近 10 个候选。范围默认以所选公寓为中心直线 500 米，支持 100–2000 米，后续换类别保留范围。
- 最近一家指直线最近，步行路线单独查询 OSRM；校园通勤使用既有 30 条 Valhalla 真实路网快照。步行时间筛选在程序执行，不由模型估算。
- SQLite WAL 保存每个匿名浏览器、每座城市的对话及页面条件。Cookie 使用随机令牌、HttpOnly、SameSite；服务端保存令牌哈希，所有读写按 owner 和会话 ID 校验。
- 会话版本及处理租约拒绝旧写入和并发覆盖；浏览器检查请求 ID、城市与手动操作版本，避免过时回答覆盖地图。刷新恢复状态，不重放历史工具动作。
- 路线缓存与 24 小时请求额度存 SQLite，进程重启仍保留。仍然按单进程串行、至少 1.1 秒间隔访问公共路线服务。
- AI 未配置时明确显示「工具体验」和禁用自然语言输入，可用按钮运行真实业务工具；固定测试模型只用于自动化验证，不作为真实 AI 能力证据。

## 模型配置

复制 `app/.env.agent.example` 为 `app/.env.agent.local`，填写：

```dotenv
ATLAS_AI_BASE_URL=https://服务商提供的地址/v1
ATLAS_AI_MODEL=服务商提供的模型名称
ATLAS_AI_API_KEY=只放本地的服务端密钥
ATLAS_CHAT_DB=.data/rental-chat.sqlite
ATLAS_AI_DAILY_LIMIT=100
```

重启 `npm run dev -- --port 5174` 或 `npm run start`。模型需支持流式 Chat Completions 与工具调用。SDK 自动追加 `/chat/completions`，Base URL 不应填完整的 completions 路径。不要使用 `VITE_` 前缀，也不能复用 Cesium token。

服务器配置可以用环境变量注入；已有进程环境变量优先于本地配置文件。API 不返回密钥、Base URL 或模型配置内容，只返回是否填写及缺失字段名。每个匿名 owner 每分钟最多 6 轮，单服务器默认每 24 小时最多 100 轮；这不是按金额精确计费。

## 普通服务器

当前默认运行目标由 Cloudflare workerd 改为 Node，支持 `node:sqlite`；Cloudflare Quick Tunnel 仍可转发这个 Node 服务。旧的 Workers/D1 部署模板不能直接运行本版 Agent。

```sh
cd rentApartment/app
npm ci
npm run build
npm run start -- --hostname 127.0.0.1 --port 3000
```

建议在 Nginx/Caddy 后运行，保留 Host、正确传递 `X-Forwarded-Proto`，对 `/api/agent/chat` 关闭代理缓冲并将读超时设为大于 90 秒；使用进程管理器维护**一个** Node 进程。部署时保留 `dist/`、`public/`、`scripts/`、`node_modules/` 和 package 文件；运行工作目录为 app。

`app/Dockerfile` 提供构建模板，AI 配置通过运行时环境传入，`.data` 挂载持久卷。构建需要浏览器可见的只读地图 token；允许的来源包含服务器网站地址。Docker 镜像构建本轮未执行。

数据库目录必须可写且不要公开静态访问。备份 SQLite 时使用一致性备份或停进程后备份数据库及 WAL；不能只复制正在写入的主文件。正式多实例部署前需迁移 PostgreSQL、共享路由配额/限流及有保障的路由服务；需要账号跨设备续聊时再接登录。当前匿名会话清除 Cookie 后不能找回。

## 验收链路与数据边界

1. 选公寓 → 问「这套公寓直线500米内有几个便利店」→ 数量与地图一致。
2. 「只显示最近一家」→ 1 个点、门店名称和直线距离。
3. 「走过去怎么走」→ 真实路网路线、预计时间和入口限制。
4. 「换成附近超市」→ 同一公寓和范围，新类别与点位。
5. 刷新 → 恢复历史、偏好和地图；切城市 → 独立会话；另一个浏览器 → 无权读取原会话。

设施依然仅为各校区周边 3 公里的 OSM 快照。回答必须说「收录数」，超出覆盖不能保证完整；0 不代表没有，最近候选不能等同步行最近。房源依然虚构，不可预订。营业状态、入口、使用资格、治安未核验，不编造安全分。

## 真实接口复测

用户填写本地配置后实测，密钥及接口地址未写入本文。先修正 Base URL 中重复的 `/chat/completions` 尾缀。最小请求返回 HTTP 200；安装版本的 AI SDK 流式输出返回「连接成功」。

首轮工具测试发现供应商网关会拒绝 `searchListings` 中 nullable 数值生成的 `anyOf` schema，即使本轮请求的是其他工具。工具改用普通数值和 `clearBudget` / `clearWalkMinutes` 标志，页面状态继续使用 null 表示未限制；预算与通勤条件清除及传给模型的参数格式均加入回归检查。

在 `http://127.0.0.1:5174/?city=london&listing=london-2` 实际输入自然语言，使用真实模型完成：

1. 查询当前公寓 500 米内便利店：回答 Chapter House 周边快照收录 14 家，地图显示 14 处。
2. 追问「那只显示离我最近的一家就好」：回答 Sainsbury's Local、直线 77 米，地图仅保留一处。
3. 追问步行路线：工具成功，地图显示 119 米、约 2 分钟。首次文字答复发生截断，将每次模型输出上限从 1200 调整至 2400 token。
4. 重新查询并要求一句话说明：真实模型完整回复目的地、119 米、2 分钟，地图路线保留。

修正后 6 项 Agent 回归测试、TypeScript 检查、变更文件 ESLint 和生产构建通过。刷新后上述真实模型历史与地图路线恢复，浏览器错误/警告列表为空。原临时分享地址的 Node 服务已重载最终构建及配置，服务、隧道、防休眠进程均在运行。此结果证明上述伦敦对话的连接、流式回复、历史指代和地图工具串联；不代表所有模型或问题均已验证。
