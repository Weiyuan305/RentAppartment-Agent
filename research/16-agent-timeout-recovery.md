# Agent 无回复与恢复

2026-10-09。现象：用户询问「每周 500 以内、到学校步行半小时以内」后，只显示用户消息，没有回复，也没有失败说明。

## 已确认的原因

- 开发服务记录该轮 `POST /api/agent/chat` 持续 90.1 秒；SQLite 中此轮仅保留用户消息，没有助手回复，租约已释放。这与路由的 90 秒 deadline 一致。
- 使用真实 AI SDK 和一个不返回数据、响应 AbortSignal 的兼容接口测试响应复现：deadline 触发后，SSE 只有 `abort`，没有 `error`。页面没有处理这一结束状态；空助手消息又被会话存储过滤，刷新后仍无提示。
- 首个回归测试在修改前失败，失败输出明确为 `abort` / `TimeoutError`，修改后通过。不是 Markdown 把已有答案隐藏了。此次供应商为何没有及时完成，现有证据不足以确认。
- 开发页面热更新还会中断正在输出的回复；旧记录可能保留 `state: streaming` 的部分文本。这类记录也应允许恢复，不能当作成功完成。

## 修改

- 将服务端 deadline 超时转换为明确错误，记录 `timeout` / `error` / `stopped` 消息状态；即使没有文字也保留失败记录。区分主动停止与模型失败。
- 页面展示原因及「重试这条消息」按钮；历史孤立用户消息、部分回复、网络失败也可重试。
- 重试先同步服务器会话版本，只重做最近一条用户消息，复用已存原文及 ID，不追加重复提问；页面现有地图条件保留。
- 兼容旧记录，无需迁移或清空聊天。服务端增加请求 ID、结果状态和耗时日志，不把提示词或密钥写入新增日志。

## 验证

- 8 项 Agent 测试通过，新增覆盖超时、失败状态刷新恢复、重试不重复用户消息、预算与通勤地图状态、供应商错误、空回复、主动停止和历史部分回复。
- TypeScript、修改文件 ESLint、生产构建通过。
- 在用户原来的伦敦会话实际点击重试，真实模型约 9.3 秒完成，返回 6 套演示房源，预算 £500/周、到 UCL 步行 30 分钟条件同步到页面。服务器记录 `completed`，文字部分状态均为 `done`。
- 刷新后完整答复及筛选保留；该提问在 SQLite 中仍只有一条。浏览器没有 error/warn，成功后不再显示重试按钮或等待状态。
- 截图：`/tmp/rental-agent-retry-success.png`。原 Cloudflare 临时预览重载同一构建，链接保持不变。

一次成功重试仅证明这条对话恢复及工具联动，不能证明供应商所有请求都能在 90 秒内完成。
